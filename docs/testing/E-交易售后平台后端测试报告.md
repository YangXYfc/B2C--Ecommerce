> 测试日期：2026-08-24

> 基线提交：`17c45a4`

## 1. 测试目标

验证 E 角色负责的购物车、订单、模拟支付、发货、评价、退款、仲裁、统计、轮播图和日志功能，确认核心状态变化、商家隔离、库存协作和平台运营数据能够在 MySQL 集成测试与真实前端联调中运行。

## 2. 测试范围

- 购物车新增、合并、修改、勾选、删除和金额计算。
- 订单创建、按商家拆单、库存扣减/恢复、支付、取消和确认收货。
- 商家订单查询、订单详情、发货和看板统计。
- 评价创建、商品评价、商家评价列表与回复。
- 退款创建、商家审核、退货、申诉和管理员仲裁。
- 管理员统计、轮播图、操作日志和路由注册。
- B/C 前端与 E 接口的实时联调。

## 3. 本次不测试的范围

- Playwright 没有点击“提交订单”，所以没有执行真实 UI 的支付→发货→收货→评价完整链路。
- 没有通过三个前端完整操作退款申请→商家审核→平台仲裁；该流程由后端集成测试覆盖。
- 未执行支付网关、物流平台、并发下单、超卖压力、定时关单和生产审计存储测试。
- 未执行大数据量统计性能测试。

## 12. 已知问题

- 没有浏览器级的完整订单和退款跨角色自动化；当前主要由服务层 MySQL 集成测试保证状态变化。
- 移动端 E2E 会修改 `user1` 的开发库购物车，当前用例没有恢复原始购物车数量，测试隔离仍可改进。
- 未验证并发下单和超卖控制，也未执行大数据量统计性能测试。
- A 端商品分页字段缺陷会在消费者 Web 进入 E 的购物车之前阻断流程，但 B 移动端不受影响。
