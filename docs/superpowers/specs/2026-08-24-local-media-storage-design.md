# 本地媒体资源与商品图片上传设计

## 背景

项目的商品、SKU、轮播图、店铺 Logo、分类图标和头像大量引用外部 URL，其中部分 `img.jd-demo.com` 地址本身无效。断网或外部资源不可访问时，消费者端、商家端和管理端会出现空白图片。商家发布商品页面目前要求手工填写图片 URL，没有真正调用后端已有的图片上传接口。

## 目标

- 项目预置图片随仓库分发，断网启动后仍可显示。
- 四个前端对同一业务对象展示同一张图片。
- 商家新增或编辑商品时可上传主图、详情图和 SKU 图片。
- 轮播图、店铺 Logo、头像、评价图片等已有图片入口复用统一上传能力。
- 数据库保存可移植的相对路径，不写死 `localhost` 或部署域名。
- 当前开发数据库可以增量迁移，无需删除和重建。

## 总体架构

后端作为统一媒体源：

```text
预置资源 -> backend/src/main/resources/static/media -> /media/**
用户上传 -> backend/upload                         -> /upload/**
                                      |
                                      v
                            数据库保存相对路径
                                      |
                                      v
                  消费者端 / 商家端 / 管理端统一读取
```

不在四个前端分别复制资源，避免重复和版本漂移；不引入 MinIO 等额外服务，保持课程项目开箱即用。

## 目录与命名

```text
backend/src/main/resources/static/media/
├─ banners/
├─ categories/
├─ products/
├─ skus/
├─ shops/
├─ avatars/
└─ common/
```

预置文件使用可读、稳定的英文名称。有效的现有 Unsplash 商品图和轮播图下载到本地，并记录来源；无效或缺失的店铺 Logo、分类图标、占位图等制作原创资源。图片优先转换为 WebP/JPG，并控制尺寸与体积。

运行时上传继续按日期和 UUID 保存到 `backend/upload/YYYYMMDD/`。该目录不进入 Git，只保留必要的目录说明；预置资源必须进入 Git。

## 数据与 URL 约定

数据库图片字段统一保存以下两类相对路径：

- `/media/products/phone-pro-main.webp`
- `/upload/20260824/uuid.webp`

上传接口返回相对路径，不返回带请求域名的绝对 URL。这样数据库可以同时用于本机、局域网和其他部署环境。

Web 开发服务器代理 `/media/**` 和 `/upload/**` 到后端。消费者移动端增加统一媒体地址转换函数：H5、Android 和微信小程序遇到相对媒体路径时，使用 `VITE_API_BASE_URL` 补全后端地址；外部绝对 URL 保持兼容。

## 后端改动

- 保留 `/api/files/images`，继续校验空文件、扩展名和 5MB 上限。
- 上传响应改为 `/upload/...` 相对路径。
- `/media/**` 使用 Spring Boot 自带静态资源目录；`/upload/**` 继续映射外部上传目录。
- 两类公开图片路径均不需要 JWT。
- 为静态资源访问、上传响应和文件落盘增加自动化测试。
- `backend/upload/` 加入 Git 忽略，避免运行时文件污染仓库。

## 前端改动

### 商家端

- 商品表单增加主图上传、详情多图上传和每个 SKU 的图片上传。
- 上传前显示类型/大小提示，上传后立即预览。
- 创建和更新商品提交后端返回的相对路径。
- 店铺设置中的 Logo 使用相同上传组件。

### 管理端

- 轮播图管理从手写 URL 改为图片上传并预览。
- 审核列表和详情兼容 `/media`、`/upload` 相对路径。

### 消费者 Web 与移动端

- 商品、SKU、购物车、订单、轮播图、分类、店铺、头像和评价图片统一经过媒体地址处理。
- 本地资源缺失时显示 `/media/common/placeholder.webp`。

## 数据迁移

- 更新 `database/data.sql`，新数据库直接写入 `/media/...`。
- 同步更新后端保留的 H2 种子脚本，避免两份种子数据漂移。
- 提供幂等迁移脚本，按稳定的种子数据 ID 更新当前 `jd_ecommerce` 中的图片字段。
- 迁移只改图片路径，不删除表、不重建数据库、不覆盖其他业务字段。

## 错误处理

- 上传失败时保留表单原值并显示后端错误消息。
- 非图片、超过 5MB、空文件返回明确的 400 错误。
- 预览加载失败时切换为本地占位图，避免无限错误循环。
- 暂不自动删除旧上传文件，避免共用图片被误删；清理机制不在本次范围。

## 验证

- 自动检查种子 SQL 不再包含运行时依赖的远程图片 URL。
- 后端上传与静态资源测试通过。
- 四个前端构建通过。
- 使用真实 MySQL 启动后，商品、轮播图、店铺和分类图片均从 `/media` 返回 HTTP 200。
- Playwright 验证消费者商品浏览链路和商家图片上传/商品表单链路。
- 临时断开外部网络或拦截外部图片域名后，种子页面仍显示完整图片。

## 非目标

- 不引入云对象存储、CDN、图片审核、自动垃圾文件回收。
- 不实现复杂裁剪器和服务端图片转码流水线。
- 不改变商品、订单、退款等业务状态机。
