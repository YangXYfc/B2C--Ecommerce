# B 角色消费者移动端设计规格

## 1. 目标

在现有多商家电商项目中新增 `frontend-user-mobile`，使用一套 uni-app 代码同时支持微信小程序、H5 本地预览和 Android App 打包。移动端覆盖消费者从浏览商品到售后处理的完整购物闭环，并直接复用 D/E 角色提供的后端 API。

本任务不新增后端接口、不修改数据库表结构，也不复制一套移动端专属后端。

## 2. 交付范围

移动端必须包含以下可导航、可操作页面：

1. 首页：品牌头部、搜索、活动轮播、生活场景入口、精选商品和底部导航。
2. 分类与搜索：一级分类、子分类、关键词、销量和价格排序、分页加载。
3. 商品详情：商品图片、价格、商家、规格选择、库存、评价摘要、加入购物车和立即购买。
4. 购物车：选择商品、修改数量、删除、全选、清除选中商品和去结算。
5. 结算：选择地址、展示按商家拆分的商品、备注、金额汇总和提交订单。
6. 订单：订单列表、状态筛选、订单详情、模拟支付、取消订单和确认收货。
7. 评价：星级、文字内容和图片地址输入，提交已完成订单评价。
8. 退款售后：退款列表、详情、申请退款、填写退货物流和申请平台介入。
9. 地址管理：列表、新增、编辑、删除和设置默认地址。
10. 账户：登录、注册、个人资料、修改密码和商家入驻申请。

## 3. 技术方案

### 3.1 基础技术

- uni-app CLI 项目
- Vue 3 Composition API
- Pinia 状态管理
- `@dcloudio/vite-plugin-uni` 构建
- JavaScript，不在本阶段引入 TypeScript
- uni-app 原生组件和少量项目自有组件，不引入大型移动 UI 库
- Vitest 测试纯函数、数据适配和状态逻辑

### 3.2 运行目标

- `npm run dev:h5`：浏览器开发预览
- `npm run build:h5`：H5 生产构建
- `npm run dev:mp-weixin`：微信小程序开发构建
- `npm run build:mp-weixin`：微信小程序生产构建
- Android：使用 HBuilderX 导入 `frontend-user-mobile` 后运行或发行原生 App

### 3.3 目录边界

```text
frontend-user-mobile/
├─ src/
│  ├─ api/              # 请求封装、业务 API、模拟 API
│  ├─ components/       # 品牌头部、商品卡、状态标签、底部安全区等
│  ├─ pages/            # 各业务页面
│  ├─ static/           # 项目自有图片和图标资源
│  ├─ stores/           # 登录用户和购物车状态
│  ├─ styles/           # 设计变量和全局样式
│  ├─ utils/            # 金额、状态、路由和存储工具
│  ├─ App.vue
│  ├─ main.js
│  ├─ manifest.json
│  └─ pages.json
├─ tests/
├─ package.json
├─ vite.config.js
└─ README.md
```

每个文件只承担一种职责。页面负责组合与交互，API 模块负责数据访问，store 负责跨页面状态，工具函数负责可测试的纯逻辑。

## 4. 视觉设计

### 4.1 已确认方向

视觉基准为 [`docs/design/b-role-user-mobile-home-concept.png`](../../design/b-role-user-mobile-home-concept.png)。

移动端使用原创品牌“悦选”，不出现“JD商城”。品牌语为“发现你的生活好物”。整体延续现有消费者 Web 端的红色电商识别，但采用生活方式橱窗和编辑式商品陈列，不照搬桌面端布局。

### 4.2 设计变量

- 品牌红：`#E4393C`
- 深红：`#C81623`
- 页面背景：`#F7F7F7`
- 主表面：`#FFFFFF`
- 主文字：`#2F2F2F`
- 次文字：`#8A8A8A`
- 分割线：`#ECECEC`
- 柔和场景背景：`#FFF1F1`
- 价格统一使用品牌红，正文以 28rpx 至 32rpx 为基础字号
- 圆角以 16rpx、24rpx 为主，阴影仅用于悬浮操作或重点媒体

### 4.3 信息架构

首页顶部由小型“悦选”品牌标识、品牌语和搜索框组成。主视觉后依次是生活场景入口、“今日精选”和商品内容。底部固定四项导航：

- 首页
- 分类
- 购物车
- 我的

其他页面沿用相同设计语言：真实商品摄影、清楚的价格层级、大触控区域、底部安全区、轻量分隔和有限的红色强调。页面不堆叠无意义卡片，不使用装饰性徽章、虚假促销或与项目数据无关的功能。

## 5. 数据与接口

### 5.1 双数据模式

应用支持两种数据模式：

- `mock`：默认开发演示模式，数据保存在 uni-app storage 中，可完整演示登录、购物车、订单、评价、退款和地址操作。
- `api`：真实接口模式，通过环境变量配置后端基础地址，并调用现有 Spring Boot API。

两个模式返回相同的页面数据结构。页面不得判断当前使用哪一种模式。

### 5.2 认证与请求

- 登录成功后保存 token 和用户概要。
- 真实请求在 `Authorization` 中携带 Bearer token。
- 收到 401 时清除本地会话并跳转登录页。
- 网络错误、业务错误和空数据分别呈现明确状态。
- 写操作成功后更新 store 或重新加载当前业务数据。

### 5.3 API 范围

接口完全依据项目分工文档和 `docs/api-contract.md`，包括：

- Banner、分类、商品和评价查询
- 购物车增删改查
- 地址增删改查与默认地址
- 创建、查询、支付、取消和确认收货订单
- 创建评价
- 创建、查询、退货物流和申诉退款
- 登录、注册、个人资料和修改密码
- 图片上传与商家入驻申请

## 6. 状态与交互

### 6.1 全局状态

- `user` store：token、登录状态、用户资料、登录和退出。
- `cart` store：购物车数量、刷新、增加后的数量同步。

订单、退款、地址和商品数据保持页面级状态，避免不必要的全局缓存。

### 6.2 反馈状态

每个数据页面必须提供：

- 首次加载状态
- 下拉刷新或重新加载
- 空状态
- 请求失败状态
- 提交中状态，阻止重复提交
- 成功反馈和可预测的返回路径

所有底部固定操作栏必须处理安全区，重要按钮触控高度不低于 88rpx。

## 7. 模拟业务规则

模拟模式遵循现有后端契约的关键规则：

- 登录演示账号为 `user1 / 123456`。
- 未登录访问购物车、结算、订单、退款、地址或个人中心时跳转登录。
- 购物车数量必须大于零且不能超过模拟库存。
- 提交订单必须有收货地址和至少一个选中商品。
- 待支付订单可支付或取消，待收货订单可确认收货，已完成订单可评价。
- 退款流程按现有状态展示允许的下一步操作。

模拟模式用于前端演示，不伪装成真实支付、物流或退款服务。

## 8. 测试与验收

### 8.1 自动化验证

- Vitest 覆盖金额格式、订单状态、分页合并、请求结果解包和模拟业务状态变更。
- `npm run test` 必须通过。
- `npm run build:h5` 必须通过。
- `npm run build:mp-weixin` 必须通过。

### 8.2 视觉与交互验证

- 以 390×844 为主要验证视口。
- 首页浏览、搜索、商品详情、加入购物车、结算、订单支付、评价和退款形成可操作闭环。
- 对照已确认概念检查品牌头部、留白、字体层级、色彩、图片裁切、场景入口、商品陈列和底部导航。
- 同时检查微信小程序构建产物中页面配置、tabBar、静态资源和分包引用有效。

## 9. 启动说明

`frontend-user-mobile/README.md` 必须包含：

- Node.js 和 npm 版本要求
- 安装依赖
- H5 开发与构建
- 微信开发者工具导入 `dist/dev/mp-weixin` 和生产产物目录
- HBuilderX 导入、Android 真机运行和发行步骤
- mock/api 模式切换
- 后端地址配置
- 演示账号
- 常见问题，包括微信合法域名、Android 网络权限和本地 HTTP 调试

## 10. 非目标

- 不新增 JWT、支付渠道、推送、地图定位、扫码、直播或优惠券系统。
- 不修改 D/E 后端业务逻辑。
- 不增加文档没有要求的营销或社交功能。
- 不在本任务中提交微信 AppID、Android 签名或任何密钥。
